# 秋招模拟器

**Autumn Recruitment Simulator** — 一款在浏览器里运行的、以「校招季」为题材的 **Roguelike 资源管理 + 叙事模拟** 小品。三十天、有限行动点、随机开局与海量事件，让你在拒信与 Offer 之间体验一届秋招能有多「真实」又有多「魔幻」。
点击这里，立刻体验：https://phlos846.github.io/-DEMO/

>只是路过？不妨开一局，看看自己是「大满贯」还是「考研 TV」。

---

## 为什么值得点开玩一局

- **每局都是新人生**：随机学历（含清北 / 985 / 海归 / 普本 / 野鸡 / 大专）、专业档位、1～3 个性格词条、0～2 个经历词条，以及 **2～3 个带稀有度的天赋**（金 / 紫 / 蓝 / 白 / 黑）。通关后还可 **重随词条** 刷开局，图鉴会记住你解锁过的一切。
- **秋招不只有投递**：每一天你要在 **休息、娱乐、学习、海投** 之间分配 **行动点**。钱、压力、精力、综合素质互相拉扯；你还可以 **每日限一次透支**——多搏一次行动，但你知道，总是要付出些什么代价。
- **岗位不是贴图**：公司带 **年薪档、待遇词条、多条社会风评、行业与隐藏信息**；刷新列表时，薪资与词条的分布会随 **你的学历期望带、求职「匹配分」（类 ELO）、综合素质** 变化——纸面弱时更容易看到「绿词条少」的岗位，履历拉满时整体薪资带与好词条倾向都会上移，招聘要求与竞争程度独立生成，待遇和风评不再直接影响通过率。
- **结局多到像成就墙**：从 **精力 / 压力崩盘**、**传销陷阱**、**彩票翻身**、**考研 / 考公 TV**、**大满贯 / 捡漏高薪**、**外包圣体**、**创业线** 到各种 **普通上岸 / 春招再战**，多条分支按优先级结算；还有事件触发的 **世界线分叉结局**。每一局的收尾文案都试图讲清「这一届你输在哪 / 赢在哪」。

## 系统设计一览

### 资源与节奏

| 维度 | 作用 |
|------|------|
| **行动点** | 日内决策预算；用尽才可结束当日，透支带来跨日惩罚。 |
| **现金 / 负债** | 娱乐、生活费与部分事件挂钩，极端走向会影响叙事结局。 |
| **压力 / 精力** | 双维生存线；过高压力或精力归零会触发 **Bad End**，强制玩家直面节奏问题。 |
| **综合素质** | 显性成长，影响过筛与岗位池分层。 |
| **隐藏：简历过筛倾向 / 面试发挥** | 学习等行为缓慢推高「看不见的手」，与天赋、词条叠加。 |
| **求职匹配分（类 ELO）** | 根据期望通过率与实际结果更新，让「海投手感」随局内表现漂移。 |

### 匹配与岗位生成（专业向摘要）

- **简历过筛** 与 **面试通过** 由多因子乘性模型驱动：学历基础率、综合素质曲线、独立的 **岗位要求 × 竞争程度** 修正、薪资档与学历期望的 **市场匹配**、隐藏属性、天赋加成、行业与特殊标签（如 211+理科对部分薪资带的修正）等。
- **薪资抽样**：以 **学历对应期望档** 为高斯中心主锚，并与匹配分偏置、综合素质带来的 **有限上移（约对应数万年薪量级）** 混合；**向上投递**（岗位薪资高于当前状态下「更容易刷到的」中心档）会对简历期望额外 **×0.8**，避免「刷高了池子却不吃惩罚」的违和感。
- **公司与面试队列**：岗位可带 **隐藏词条**（例如你懂的「那种」Offer）；面试按日排队，与行动点、事件穿插，文本池多 variant，减少复读感。

### 内容厚度

- **大量随机事件**（含娱乐衍生、学习过劳、顿悟、行业短期 buff 等），与 **图鉴**（`localStorage` 持久化解锁）配合，适合多周目收集。
- **天赋与性格** 改变同一行动的消耗与收益，鼓励不同 build；金色天赋里既有 **大心脏、高效率**，也有 **天才、关系户** 这类强 fantasy，方便玩家自我投射或吐槽现实。
- **结局与 Offer 结算**：多结局按条件优先级判定；Offer 可排序、可选主 Offer，结算展示与玩梗公司名（neta）共存，兼顾可读性与话题性。

##和其他的模拟经营游戏，不一样在哪里？

1. **显性目标 vs 隐性成长**：玩家看得见的「综合素质」与看不见的「过筛 / 面试倾向」分层，类似 RPG 里 **可见等级 + 隐藏匹配分**，便于做长期养成而不把 UI 撑爆。
2. **动态难度 / 手感**：类 ELO 的求职分让同一套公式在不同局、不同阶段给出不同「市场反馈」，接近 **在线匹配里 MMR 调节体验** 的思路，只是单机构成了闭环。
3. **程序生成与分层抽样**：岗位不是纯随机，而是 **条件分布**（学历、综合素质、匹配分共同塑造池子），招聘难度则由独立字段决定，这是在控制 **玩家可感知公平性** 时的典型手法。
4. **风险—收益显性化**：透支行动点、高压线、传销与网贷梗等，都是 **用规则讲伦理与代价**，和关卡里「贪刀惩罚」同源，只是母题换成了求职。
5. **叙事与机制同构**：考研 / 考公用 **隐藏学习累计 + 分段概率** 与 Offer 数量惩罚挂钩，结局不是纯文案按钮，而是 **状态机自然结果**——这是任务策划常说的 **mechanic-narrative alignment**。
6. **收集与多周目**：图鉴驱动重复游玩，和手游里 **图鉴 / 成就** 拉长轻量游戏的寿命同一逻辑。

我们不是在声称「模拟真实招聘流程」，而是在用 **可玩的抽象** 讨论：**有限资源、信息不对称、随机性与一点点黑色幽默** 如何组成一届令人难忘的秋招。

## 本地运行

### 交互式随机事件

新增 28 个事件（24 个专属决策、4 个通知），配置在 `js/eventExpansion.js`，均为单局一次。
在符合条件、冷却和单局次数限制的候选中，先以 70% 概率选择交互池，再按事件权重抽取。新局首个随机事件、连续两条通知后的下一次随机抽取，会在有合格交互候选时优先选择交互。普通与娱乐入口均采用此规则；同日队列规划也会考虑连续通知数。没有合格交互候选时正常选择通知，不突破冷却。
此机制提高交互覆盖率，不额外增加每日弹窗数量。天赋的感冒触发仍保留，属于交互事件。抽样测试覆盖 200 个固定种子的 30 天事件安排，不代表完整游玩的存活率或数值平衡。

同局随机事件默认冷却 5 个自然日（第 2 天出现，最早第 7 天再出现），抽取权重依次为原权重的 100%、30%、10%，以后保持 10%。这些是相对权重，不是绝对触发概率。
学长内推、副业机会、彩票头奖、移民中介、学分预警、猎头急电单局最多出现一次，拒绝也计次。每天的事件队列内不重复，娱乐事件和天赋触发共用历史限制；候选池为空时不强制补事件。
历史在弹窗展示时记录，未展示的排队事件不计次；新局重置。学习过劳与顿悟属于行为触发状态，保留原触发规则。
事件可用 `maxPerRun`、`cooldownDays`、`repeatWeightDecay` 覆盖默认规则。运行全部测试：`node --test tests/*.test.mjs`。

事件按情境分为通知、决策和事实发生后的应对，不再强制每个事件提供选项。

- 中奖、拒信、顿悟和多数已经发生的生活事件，展示时结算，仅需点击「继续」。
- 内推、副业、甲方改需求、考试、模拟面试等使用专属选项；没有通用的「调整状态」分支，也不再奖励拒绝行为。
- 感冒先扣除精力、施加病后状态，再选择如何休养；休养不会撤销已发生的影响。事实影响导致失败时不能再选恢复选项。
- 请学长批改简历会在两天后收到批注；付费副业先收定金，两天后处理尾款。临近截止时提前回复，最晚当天排入后续队列。主动提前结束或中途失败会终止尚未完成的故事。
- 现金、行动点不足的选项不可选；恢复量和消耗量继续受天赋、临时状态及上限影响。
- 移民、毕业与口头意向仍是人生决定；彩票头奖恢复为事实通知并保留原结局。学习过劳和顿悟恢复为状态通知。

配置见 `js/eventChoices.js`，未配置的事件默认通知。`beginEvent` 只执行一次事实影响，`resolveEvent` 只执行一次所选分支；二者不重复计次。后续事件按 ID 和到期日记录，列入图鉴，不挤占随机事件次数。

使用 Node.js 24 执行交互事件回归检查：`node --test tests/event-choices.test.mjs`。

本项目为 **静态前端**（原生 HTML / CSS / JS 模块），需通过 **本地 HTTP 服务** 打开（直接 `file://` 打开可能导致模块脚本无法加载）。

**方式一（Windows）**：双击仓库内 `start.bat`。

**方式二**：在项目根目录执行：

```bash
python -m http.server 8765
```

浏览器访问：`http://127.0.0.1:8765`

（仓库中亦提供 `serve.ps1` 等辅助脚本，可按环境选用。）

## 技术说明

- **无框架**：模块化 ES Modules，便于单文件职责清晰（状态、匹配、事件、结局、图鉴等拆分）。

- **AI**：本项目使用Cursor一键生成代码——100%AI，当然，设计还是人做的。

### 招聘与状态修正

- 岗位要求：基础 ×1.08、常规 ×0.94、较高 ×0.80；竞争：较少 ×1.04、一般 ×1、激烈 ×0.90。两项各按 25% / 50% / 25% 稳定生成，影响简历筛选和面试。薪资匹配系数保留。
- 面试状态：精力 ≥20 且压力 ≤80 时系数为 1。精力系数为 `0.4 + 0.6 × clamp(精力/20, 0, 1)²`，压力系数为 `0.4 + 0.6 × clamp((100-压力)/20, 0, 1)²`；在原面试概率上下限处理后乘上两者，极端情况下可低于原 2.5% 下限。作弊及传销陷阱的必过规则保留。
- 综合素质沿用原成长、上限及存储字段，仅统一名称。
