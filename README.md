# 秋招模拟器

**Autumn Recruitment Simulator** — 一款在浏览器里运行的、以「校招季」为题材的 **Roguelike 资源管理 + 叙事模拟** 小品。三十天、有限行动点、随机开局与海量事件，让你在拒信与 Offer 之间体验一届秋招能有多「真实」又有多「魔幻」。

>只是路过？不妨开一局，看看自己是「大满贯」还是「考研 TV」。

---

## 为什么值得点开玩一局

- **每局都是新人生**：随机学历（含清北 / 985 / 海归 / 普本 / 野鸡 / 大专）、专业档位、1～3 个性格词条、0～2 个经历词条，以及 **2～3 个带稀有度的天赋**（金 / 紫 / 蓝 / 白 / 黑）。通关后还可 **重随词条** 刷开局，图鉴会记住你解锁过的一切。
- **秋招不只有投递**：每一天你要在 **休息、娱乐、学习、海投** 之间分配 **行动点**。钱、压力、精力、简历完整度互相拉扯；你还可以 **每日限一次透支**——多搏一次行动，但你知道，总是要付出些什么代价。
- **岗位不是贴图**：公司带 **年薪档、待遇词条、多条社会风评、行业与隐藏信息**；刷新列表时，薪资与词条的分布会随 **你的学历期望带、求职「匹配分」（类 ELO）、简历完成度** 变化——纸面弱时更容易看到「绿词条少」的岗位，履历拉满时整体薪资带与好词条倾向都会上移，同时用微调保持 **期望通过率** 不会因此被数值「骗」崩。
- **结局多到像成就墙**：从 **精力 / 压力崩盘**、**传销陷阱**、**彩票翻身**、**考研 / 考公 TV**、**大满贯 / 捡漏高薪**、**外包圣体**、**创业线** 到各种 **普通上岸 / 春招再战**，多条分支按优先级结算；还有事件触发的 **世界线分叉结局**。每一局的收尾文案都试图讲清「这一届你输在哪 / 赢在哪」。

## 系统设计一览

### 资源与节奏

| 维度 | 作用 |
|------|------|
| **行动点** | 日内决策预算；用尽才可结束当日，透支带来跨日惩罚。 |
| **现金 / 负债** | 娱乐、生活费与部分事件挂钩，极端走向会影响叙事结局。 |
| **压力 / 精力** | 双维生存线；过高压力或精力归零会触发 **Bad End**，强制玩家直面节奏问题。 |
| **简历完整度** | 显性成长，影响过筛与岗位池分层。 |
| **隐藏：简历过筛倾向 / 面试发挥** | 学习等行为缓慢推高「看不见的手」，与天赋、词条叠加。 |
| **求职匹配分（类 ELO）** | 根据期望通过率与实际结果更新，让「海投手感」随局内表现漂移。 |

### 匹配与岗位生成（专业向摘要）

- **简历过筛** 与 **面试通过** 由多因子乘性模型驱动：学历基础率、简历完整度曲线、公司 **好 / 一般 / 坏** 词条数量修正、薪资档与学历期望的 **市场匹配**、隐藏属性、天赋加成、行业与特殊标签（如 211+理科对部分薪资带的修正）等。
- **薪资抽样**：以 **学历对应期望档** 为高斯中心主锚，并与匹配分偏置、完成度带来的 **有限上移（约对应数万年薪量级）** 混合；**向上投递**（岗位薪资高于当前状态下「更容易刷到的」中心档）会对简历期望额外 **×0.8**，避免「刷高了池子却不吃惩罚」的违和感。
- **公司与面试队列**：岗位可带 **隐藏词条**（例如你懂的「那种」Offer）；面试按日排队，与行动点、事件穿插，文本池多 variant，减少复读感。

### 内容厚度

- **大量随机事件**（含娱乐衍生、学习过劳、顿悟、行业短期 buff 等），与 **图鉴**（`localStorage` 持久化解锁）配合，适合多周目收集。
- **天赋与性格** 改变同一行动的消耗与收益，鼓励不同 build；金色天赋里既有 **大心脏、高效率**，也有 **天才、关系户** 这类强 fantasy，方便玩家自我投射或吐槽现实。
- **结局与 Offer 结算**：多结局按条件优先级判定；Offer 可排序、可选主 Offer，结算展示与玩梗公司名（neta）共存，兼顾可读性与话题性。

##和其他的模拟经营游戏，不一样在哪里？

1. **显性目标 vs 隐性成长**：玩家看得见的「简历完整度」与看不见的「过筛 / 面试倾向」分层，类似 RPG 里 **可见等级 + 隐藏匹配分**，便于做长期养成而不把 UI 撑爆。
2. **动态难度 / 手感**：类 ELO 的求职分让同一套公式在不同局、不同阶段给出不同「市场反馈」，接近 **在线匹配里 MMR 调节体验** 的思路，只是单机构成了闭环。
3. **程序生成与分层抽样**：岗位不是纯随机，而是 **条件分布**（学历、完成度、匹配分共同塑造池子），并做 **期望通过率补偿**，这是在控制 **玩家可感知公平性** 时的典型手法。
4. **风险—收益显性化**：透支行动点、高压线、传销与网贷梗等，都是 **用规则讲伦理与代价**，和关卡里「贪刀惩罚」同源，只是母题换成了求职。
5. **叙事与机制同构**：考研 / 考公用 **隐藏学习累计 + 分段概率** 与 Offer 数量惩罚挂钩，结局不是纯文案按钮，而是 **状态机自然结果**——这是任务策划常说的 **mechanic-narrative alignment**。
6. **收集与多周目**：图鉴驱动重复游玩，和手游里 **图鉴 / 成就** 拉长轻量游戏的寿命同一逻辑。

我们不是在声称「模拟真实招聘流程」，而是在用 **可玩的抽象** 讨论：**有限资源、信息不对称、随机性与一点点黑色幽默** 如何组成一届令人难忘的秋招。

## 本地运行

本项目为 **静态前端**（原生 HTML / CSS / JS 模块），需通过 **本地 HTTP 服务** 打开（直接 `file://` 打开可能导致模块脚本无法加载）。

**方式一（Windows）**：双击仓库内 `start.bat`。

**方式二**：在项目根目录执行：

```bash
python -m http.server 8765
```

浏览器访问：`http://127.0.0.1:8765`

（仓库中亦提供 `serve.ps1` 等辅助脚本，可按环境选用。）

### 可选作弊码

开局前输入框可填作弊码（详见游戏内说明）；正常游玩留空即可。

## 技术说明

- **无框架**：模块化 ES Modules，便于单文件职责清晰（状态、匹配、事件、结局、图鉴等拆分）。
- **构建**：可选脚本将多文件打 bundle（见 `build-bundle.ps1` / `build_bundle.py`），按需使用。
-**AI**：本项目使用Cursor一键生成代码——100%AI，当然，设计还是人做的。
